# Hy-Climb 제품 위키

## 제품 문서 안내

이 문서는 기존 링크와 stable ID 참조를 위한 제품 랜딩이다. 상세 보조 문서는 아래에서 확인한다.

- [이해관계자 카탈로그](03-product/01-stakeholder-catalog.md): `STK-001`부터 `STK-005`까지의 이해관계자 정의를 따로 확인한다.
- [STK-003 운영 권한 모델](03-product/02-operational-authority.md): Proposed CMS 후보와 현재 static SPA 운영 권한 경계를 따로 확인한다.

## 문서 범위

이 문서는 현재 저장소에 구현된 Hy-Climb MVP의 제품 동작만 정리한다. 서비스는 Hy-Climb 동아리원이 클라이밍 센터를 모바일 웹에서 찾고, 상세 정보를 확인하고, 네이버 지도로 길찾기를 여는 정적 웹 서비스다. 백엔드, 인증, CMS, 분석, 예약, 결제, 운영자 화면은 현재 구현 범위에 없다.

기준 소스는 `CLAUDE.md`, `component-spec.md`, `data-schema.md`, `tasks.md`, `src/pages`, `src/components`, `src/contexts`, `src/data`, `src/i18n`, `src/utils`, `public/_redirects`다. `docs/wiki/03-product.md`는 최초 작성 전 존재하지 않았다.

## Proposed CMS 전환 메모

상태: `Proposed`. 이 메모는 현재 구현 기준이 아니다. 근거는 `docs/wiki/03-product.md`의 현재 범위 밖 항목, `.omo/evidence/cms-content-authority-baseline.json`의 CMS 범위 확인, 그리고 `docs/wiki/01-index.md`와 `docs/wiki/02-governance.md`의 Proposed 상태 계약이다. Trigger는 향후 파일 편집 대신 CMS로 운영 데이터를 관리하려는 전환 검토다. 영향 받는 기존 개념은 `STK-003`, `GOAL-005`, `REQ-003`, `REQ-006`, `REQ-011`, `REQ-014`, `REQ-016`, `REQ-017`, `REQ-018`, `REQ-019`, `REQ-020`, `UC-014`, `UC-015`, `FEAT-008`, `FEAT-009`다. 새 stable role ID는 만들지 않는다. Product Owner의 명시 결정 전에는 구현 범위, 데이터 모델, 권한 정책, stable ID, 제품 범위 변경의 기준이 아니다.

`운영 콘텐츠`는 정확히 다음 여섯 categories만 뜻한다.

1. `센터 카탈로그`
2. `운영 이벤트·정기모임`
3. `다국어 콘텐츠`
4. `미디어 자산`
5. `공통 운영·외부 연동 설정`
6. `게시·검증 메타데이터`

역할 경계는 다음과 같다. `콘텐츠 운영자`는 future CMS에서 위 여섯 categories의 운영 콘텐츠를 관리한다. `인증된 콘텐츠 게시 승인자`는 그 CMS 안에서 승인된 운영 콘텐츠를 독립적으로 게시할 수 있다. Product Owner는 데이터 모델, 정책, stable ID, 제품 범위 변경 결정을 계속 책임진다. 이 CMS 권한은 public static SPA 접근 권한과 분리된다. 현재 public static SPA에는 runtime auth 또는 RBAC이 없다. CMS는 public app login이 아니며, 공개 앱 사용자를 인증해 콘텐츠 편집 권한을 주는 흐름도 아니다.

Non-goal: 이 메모는 현재 앱에 로그인, RBAC, 관리자 화면, CMS 런타임, 자동 게시, 공개 사용자 권한을 추가하지 않는다. `인증된 콘텐츠 게시 승인자`가 없는 상태에서 자동 게시하는 정책도 만들지 않는다. Product Owner를 schema 또는 policy 결정에서 제외하지 않는다. CMS를 public login으로 설명하지 않는다.

## 현재 데이터 기반 동작 요약

현재 `centers.json`에는 `center_01`부터 `center_11`까지 11개 센터가 있다. 지역은 수원, 안양, 군포, 서울이 포함된다. 제휴 센터는 `center_01`, `center_02`, `center_03`이다. 일부 센터만 전화번호, 제휴 가격, SNS, 주차 정보를 갖는다. 앱은 선택 필드가 없는 센터에서도 상세 페이지를 표시하고, 없는 섹션만 생략한다.

현재 `config.json`에서 이벤트와 정기모임은 모두 `active: false`다. 따라서 기본 홈 화면에는 배너가 보이지 않는다. 구현은 설정값을 켰을 때의 이벤트 배너와 정기모임 배너 흐름을 포함한다.
